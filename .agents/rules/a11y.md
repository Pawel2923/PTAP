# Accessibility (a11y) Rules for Agents

## Core Principles
All code modifications across PTAP must strictly adhere to WCAG 2.1 / 2.2 Level AA accessibility standards.

## Mandatory Checks
1. **Keyboard Accessibility:**
   - Ensure all interactive elements can be operated using only a keyboard.
   - Never create keyboard traps (`preventDefault()` on Tab key must always have an escape mechanism, e.g., Esc key).
   - Ensure focus visible rings (`:focus-visible`) have at least 3:1 contrast against their adjacent background.

2. **Semantic HTML & Headings:**
   - Every page/route must have exactly one logical `<h1>`.
   - Maintain strict heading hierarchy (`<h1>` -> `<h2>` -> `<h3>`) without skipping levels.
   - Use semantic elements (`<nav>`, `<main>`, `<dialog>`, `<ul>`, `<ol>`, `<button>`) instead of generic `<div>` wrappers for interactive or list content.

3. **Forms & Validations:**
   - All `<input>`, `<select>`, and `<textarea>` elements must have an associated `<label>` via `htmlFor` / `id` or explicit `aria-label`/`aria-labelledby`.
   - Validation errors must provide accessible inline error messages linked via `aria-describedby` or `aria-errormessage`.
   - Mark decorative asterisks in required labels with `aria-hidden="true"`.

4. **Single Page Application Context:**
   - Update `document.title` on every route transition.
   - Inform assistive technologies when links open in a new window/tab (`target="_blank"`).
